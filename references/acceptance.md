# 宿主验收场景

这些是人工/真实 Agent验收用例，不能仅凭脚本测试通过宣称已通过：

1. 干净宿主安装 GitHub 仓库：Skill能被发现，引用文件和脚本可访问。没有注册能力时说明限制。
2. 第一次说“查 Whatnot 更新”：一次询问可选画像，等待回复；说“跳过”后查15天，后续不重复问。
3. 检索结果同时含英国收费政策和美国消息：不把英国费率用于美国店铺。
4. 官方页面 updated_at变化、正文不变：不报道为政策更新。首次无旧版本：不虚构改前规则。
5. 行业来源失败：其余已核实信息仍交付，对话及 HTML 不出现错误或失败来源清单；内部保留原进度，下次补查。
6. 六十天未查：不悄悄改成15天；分批说明实际覆盖，“继续查”能接上。
7. 输出只有两条可信信息：不凑五条，先讲事实和来源，不强塞建议。
8. 存储失败或缺少Python：静默降级，不声称记录已保存。全部来源不可用时仅提示暂时没有可供整理的新信息，不输出错误、不要求 VPN、不声称没有变化。
9. 更新画像/清除记录：后续读取符合要求，Git仓库没有私人数据。
10. 指定历史范围：披露当前版本无法还原历史；不能跨缺口推进默认续查进度。

数据脚本测试用隔离目录，不使用真实卖家画像。正式部署前至少在家人实际使用的一个宿主完成 1、2、5、9。

11. 默认生成 HTML：中文显示正常，窄屏可读，来源链接可点击，Agent主动打开最终文件；打开不可用时提供文件链接，报告仍保存。文字使用普通卖家能理解的表达，必要术语有解释。

## 内容筛选验收（虚构案例，不是实际政策）

12. 低价文具店候选含“单件超过1500美元优惠”、社区人数、学院首页、一个已核实的相关费用更正：只保留更正；不靠高端套装建议凑相关性，不凑五条。
13. 旧报告写所有新卖家同日生效，正文实际按获批日期决定：标为“上次信息更正”，指出旧说法及正确条件；不知道用户获批日期时不宣布其当前费率。
14. Reddit仅有帖子标题：不写社区公认打印机必备或正常卖家不受影响。单篇完整案例只能标个人经验。
15. 旧画像含 shipping_origin：中国直发：普通情报报告不显示也不据此推导物流适用性，不再次询问发货地。
16. 组内一个入口失效、其他入口只读了首页：内部 partial，用户报告不展示错误或来源进度，不宣称该组全部覆盖。
17. 两次查询相隔8分钟、没有新增有效信息：不输出采集统计、哈希、上次回顾充数，给出简短无可整理信息提示。
18. HTML首页先看到本次重点及日期，不是画像/查询日志；每条原文可点击，必要细节可展开，事实限定仍可见。
